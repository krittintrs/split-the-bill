# Split the Bill — Status

**Phase:** 10 — #33 rounding absorber shipped as v0.7.0: `computeBill()` still ceils every peer's total independently, once, exactly as ADR-0001 always did (two peers who ticked identical items still land on identical totals). Once every item is ticked, the bill-wide leftover — `Σ(each peer's independent ceiling) − receiptTotalSatang`, provably always ≥ 0 (ceiling is superadditive) — is subtracted from one named peer instead of staying an invisible windfall: default the organizer's self-peer, organizer-overridable via `BillInput.roundingAbsorberPeerId`, falling back to whichever peer has the largest ceil'd total if unset, stale, or would go negative. `BillResult.billLeftover` exposes exactly when a picker is needed; a shared `RoundingLeftoverBadge` component (leftover chip → expandable picker with a labeled shuffle option, worded as a subtraction: `−฿0.02 → name`) surfaces it once, in the `รวมต่อคน` footer row of the organizer's matrix/cards totals — peers only ever see the resulting tied totals, no picker anywhere. Several rounds of live click-through testing after the core mechanism landed fixed a display-only tail: dropdown clipping under a sticky row (fixed via a `document.body` portal), mismatched font sizes and a missing per-item share line on the desktop matrix, the mobile totals bar staying collapsed by default, a peer-view alignment shift with no rounding explanation on desktop, the picker opening off-screen from `CardsView`'s bottom-pinned bar, and — last — the organizer's `÷n = ฿x ต่อคน` line silently baking in Service charge and VAT while peers' own item lines (`itemShare.ts`) stayed raw; both now show the same raw per-item share, and a `รวมเป็นเงิน` subtotal row was added to both desktop matrix footers so the subtotal → SC → VAT → total waterfall has a visible baseline. This supersedes a same-day two-tier design (item-level + bill-level pickers, `line_items.rounding_absorber_peer_id`) that shipped and was reverted before merge: it needed two UI controls and could produce a negative bill-tier remainder from item-tier ceiling compounding. See ADR-0011 (refines ADR-0001; the ADR's own first draft is the reverted v1). Before it, Phase 9 shipped #20 calculation breakdown + #34 calculation bug together as v0.6.0: `computeBill()` decomposed its pipeline into three visible stages (subtotal → +service charge → +VAT) at both bill level and per peer, exposed as `BillResult` fields (`subtotalSatang`, `serviceChargeSatang`, `vatSatang`, `peerBreakdowns`); VAT is always the residual line so the three displayed numbers sum exactly to the total. Wired into four UI surfaces: the organizer's percent inputs get a permanent "%" suffix plus 5%/10% SC and 7% VAT quick-fill chips, the เช็คกับใบเสร็จ section shows a stacked line-by-line breakdown instead of one opaque figure, both matrix tables (`/bills/[id]` and `/b/[id]` desktop) gained SC/VAT footer rows plus a conditional ส่วนลด row, and the peer's own claimed row on mobile shows their personal subtotal → SC → VAT breakdown. #34 turned out not to be a code bug (SC/VAT fields were typed as 100% instead of 5%/7% with no unit hint) — this UX work is its fix, so it closes alongside #20. Before it, v0.5.0 (PR #32) shipped #24 organizer self-peer. #21 grilled 2026-08-31 (see Decision Log); plan at `docs/plans/PLAN-21-create-bill-rpc-toast.md`. #38 FX rate grilled 2026-09-01 (see Decision Log), filed as a new READY issue. → next: #21 (planned, ready for an agent), #38 FX rate, #11 dashboard, #12 my debts

**Open from the 2026-07-26 triage:** #27 Microsoft sign-in (needs a go/no-go against the Google-only decision above). #21 grilled 2026-08-31, moved to READY. #36 (visual-feedback audit) filed as a follow-up. See the issues for briefs and open questions.

## Frame (decided 2026-07-14)

- **Scale:** personal — organizer signs in with Google (Supabase Auth); peers use unguessable links, no accounts.
- **Primary actor:** bill payer (organizer): create bill → share link in the team chat (Slack) → collect payback via PromptPay QR.
- **Secondary actor:** peer: open link, tick own items, see own total, mark paid.
- **MVP (v1):** bill editor (menu items, prices, discounts as amount/% + per-item/whole-bill, service charge, VAT), who-ate-what matrix, per-person totals + checksum, shareable link with peer self-ticking, PromptPay QR per peer with exact amount, paid tracking, bill history, cross-bill "who owes me" rollup by peer name.
- **Done for v1:** the team uses it for a real lunch instead of the Google Sheet.
- **Stack:** Next.js (App Router, TypeScript) + Tailwind on Vercel; Supabase (Postgres, Auth, Realtime).
